# Minecraft 1.18.2 兼容说明

`-Pmc=1.18.2` 构建单独的 `build/minecraft-1.18.2/libs/neofabric-1.18.2-1.2.0.jar`（本地默认附加 `+local`）。这是 Loader jar，需要交给启动器的 Fabric 客户端配置作为库使用。Java 21 启动 Gradle，1.18.2 的编译器和游戏运行时使用 Java 17。常规构建可继续使用原命令；两种目标的 Loader 输出目录不同。

| 位置 | 适配及原因 |
| --- | --- |
| `settings.gradle`、`gradle/minecraft-1.18.2.gradle` | 使用独立 Loom consumer 和目标源目录。共享 Loader 代码从当前树构建，无需另维护整套旧 Loader。 |
| `src/minecraft1182/java/…/NeoFabricGameVersion.java`、目标 `fabric.mod.json` | 目标 jar 的运行时白名单和依赖元数据都限定 1.18.2；Java 最低 17。发布的 NeoFabric 仍使用版本 1.2.0，0.14.25 只用于独立的官方 Fabric 基线。 |
| 目标 API 索引和资源 | 按原有 SHA-512 检查加载 Fabric API 0.77.0+1.18.2（含其嵌套模块）。其他版本的 API 不会进入这个 jar。此 API 自身要求 Fabric Loader ≥0.14.9，基线使用 0.14.25。 |
| 目标的 `ModDiscoverer` | 构建时只替换共享解析器的一处门禁判定。1.18.2 兼容模式接受普通 Fabric 模组及 NeoConverter 标记模组，两者仍须通过 Fabric 元数据和依赖解析；1.20+ 的常规 jar 保留原门禁。 |
| `minecraft/minecraft-test-1.18.2` | 用 Yarn 1.18.2+build.4 验证 `MinecraftClient` 映射，通过 `Registry.ITEM` 执行注册表测试；1.20+ 使用的 `Registries` 与物品数据组件不进入这个测试目标。 |
| `.github/workflows/build.yml` | 1.18.2 独立构建和上传。标准构建的回归仍覆盖以往 18 个目标，PR 中比较标准 Loader 的 MD5，容器不同则逐个比对条目内容。 |

Loader 入口仍为 `net.fabricmc.loader.impl.launch.knot.KnotClient`。保留当前 Sponge Mixin 0.8.7；1.18.2 Fabric API 自带该版本 Minecraft 的注入点。基线模板改用 Yarn 命名时，`ResourceLocation` 映射为 `Identifier`，服务端 `loadLevel` 映射为 `loadWorld`。

1.18.2 无物品数据组件 API。需要 1.20+ 的 API、注册表或注入位置的模组必须使用作者提供的 1.18.2 版本。由于目标已内置 Fabric API，安装其他模组时保留一份同版本 API 即可。当前 NeoFabric Installer 的公开版本只提供原有游戏版本；此 PR 提供 Loader 构建产物，可使用继承 1.18.2 的自定义启动器配置，依赖清单取自目标 jar 内的 `fabric-installer.json`，并使用 1.18.2 Intermediary。

官方模板基线来自 FabricMC/fabric-example-mod 的 `1.18` 分支，提交 `db872c503f306c8abd8ddaf9f88e4b4c00fa0499`。独立构建固定了 Gradle 9.1.0、Loom 1.11.8、Yarn build.4、Java 17、Fabric Loader 0.14.25、Fabric API 0.77.0+1.18.2。
